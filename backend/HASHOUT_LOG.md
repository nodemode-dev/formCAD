## Display list and text pipeline · _v0.3.0 (app/display/, app/text/, app/routers/display.py, app/data/fonts/formcad-stroke.json)

`GET /api/docs/{id}/display?since=<rev>&space=<model|layout name>` answers the contract item shape from a per document, per space `DisplayState` (display/state.py) that keeps one JSON fragment per entity and joins fragments into the response, so a full response is a string join and a delta never re-encodes untouched items. `since` omitted, older than the first build's floor (newest layer, linetype, text style or header revision seen when the state was first built) or newer than the document revision gives `full: true`; otherwise only items whose fragment changed after `since` come back, plus `removed` handles (erased, moved to another space, hidden by layer, visibility or isolate, or no longer drawable). Detection uses `ent_rev`, `removed_rev` and `space_rev`; a change to LTSCALE, LWDEFAULT, PDMODE, PDSIZE, FILLMODE, TEXTFILL, FONTALT, FONTFALLBACK, the linetype or text style tables or the session hidden set rebuilds every item and compares fragments; a layer change rebuilds only that layer's items (and block users); block edits rebuild the inserts that use the block. When nothing bumped `rev` but the display changed, the state calls `doc.bump("display")` so `since` stays truthful. `order` is a sparse key (1024 apart, appended items get last plus 1024, restored items get the midpoint) so erasing one item never renumbers its neighbours; only a draw order change renumbers. Line items use a format string fast path (a test proved it equals the generic builder byte for field).

Resolved properties: index and true colours (`#RRGGBB` strings or `[r,g,b]`) through the 256 entry index table (palette.py, generated by hue, five brightness levels 255, 165, 127, 76, 38 and the half saturation variants; 8 and 9 follow the spec values), ByLayer and ByBlock (block parents), `color7` for index 7 reached directly, by layer or by block; lineweight ByLayer, ByBlock, Default (LWDEFAULT, out of range falls back to 0.25), always sent resolved with the top level `lwdisplay` flag so the renderer toggles without a refetch; transparency capped at 90 percent as 0 to 0.9, top level `trdisplay`; linetype pattern in drawing units with positive dash, negative gap, zero dot (text and shape elements dropped, equal sign runs merged), `scale` = LTSCALE times the entity's own scale times the enclosing insert scales (CELTSCALE only seeds the entity's own scale when a command creates it, which `Context.stamp` already does); continuous patterns send `lt: null`; `lt.gen` marks polylines with linetype generation. PSLTSCALE has no effect until viewports exist.

Extra fields beyond the contract, all optional for the renderer: `color7`, prim `c` (RGB) and `c7` for per run colours from `\C` and `\c` (index colours are converted before sending), part level `color`, `color7`, `lw`, `lt` inside insert and dimension block compounds, point `rel` (percent of view height when PDSIZE is zero or negative) and `rot`, layer summary `color7` and `plot`, the top level `lwdisplay` and `trdisplay`. Polyline widths come as `fill` prims with one ring per sub segment (non zero fill). Hatch: solid fill rings, or parallel line `pl` prims from a small pattern table (ANSI31 family, LINE, NET, ANGLE, STEEL; unknown names use 45 degrees); gradients draw solid; full pattern libraries are not built. Dimensions draw only their geometry block (when `block` names one) and otherwise send an empty compound with bounds. Block arrays honour `rows`, `cols`, `row_spacing`, `col_spacing` keys if present.

Text (app/text/): `fonts.py` resolves a style font by stroke names (txt, simplex, romans, anything ending .shx falls to FONTALT then the stroke font), installed file stem, installed family name (name tables read lazily, bounded), FONTALT, then the built in stroke font; per character fallback is FONTFALLBACK, FONTALT, well known wide coverage faces, then a bounded scan (60 files, 512 MB), then the stroke font, then a missing glyph box; wide (CJK) characters fill a one height square cell. System folders: macOS `/System/Library/Fonts`, `Supplemental`, `/Library/Fonts`, `~/Library/Fonts`; Windows `%WINDIR%\Fonts` and the per user folder; Linux `/usr/share/fonts`, `/usr/local/share/fonts`, `~/.fonts`, XDG data folders; plus `<data>/fonts` and `FORMCAD_FONTS`. Outlines come from fontTools 4.68.0 (MIT) flattened at 0.0007 of cap height; text height equals cap height. Outline glyphs are triangulated once per face and character (ear clipping with hole bridging, `tri.py`, original code) and become `tri` prims when TEXTFILL is on, closed `pl` outlines when off; stroke glyphs become `pl` prims. The default stroke font is an original design (`formcad-stroke.json`, ASCII plus degree, plus-minus, diameter and bullet on a 6 by 8 grid, Apache-2.0). Single line text follows the C5 justification rules (alignment point versus insertion, aligned scales height, fit scales width, bottom is a third of a height below baseline for the stroke font, Middle centres on ink extents); backwards and upside down mirror about the alignment point. MTEXT supports every inline code in C5 (`\P \N \~ \\ \{ \} \L \l \O \o \K \k \S \f \H \W \Q \T \C \c \A \p`, `^I ^J ^ `, percent codes), word wrap, tabs of each kind, centre, right, justified and distributed paragraphs, space before and after, at least and exactly spacing, nine attachments and static or dynamic columns. Not built: bidirectional reordering, Arabic joining and Thai shaping, lists generated from `\p` (a bullet, a tab and a hanging indent work as written), kerning.

Entity units decision: text and mtext rotation, text oblique and text style oblique are radians (as arc angles are). The fixtures `lines-100k.fcad` and `text-codes.fcad` were made by the document service in one transaction each. Measured on this machine (single process, Python 3.12): lines-100k open 3967 ms; first `GET /display` (cold build plus HTTP) 1186 ms, 100,000 items, 45,494,868 bytes; warm full response 135 ms; `since=rev` with no change 1 ms and 1255 bytes; one new LINE then `since` 40 ms and 1619 bytes (one item), undo reports the handle as removed, redo returns it with `order` last plus 1024; LTSCALE 1.0 to 2.0 rebuilt in 1415 ms and returned the 77,179 items that carry a pattern; text-codes full 155 ms, 467,104 bytes, 61 items.

## Canvas input, jigs, selection and grips · _v0.3.0 (app/cmd/runner.py, jig.py, snaps.py, grips.py, prompts.py, context.py, app/routers/canvas.py, app/routers/docs.py)

`POST /api/docs/{id}/input` takes `{text}`, `{point, snap?}`, `{pick}` or `{selection}`; the runner routes each into the same prompt machinery as typed text (frames for FROM, M2P and the rest, selection prompts, point and distance and angle prompts). Command-line state gains `expect`, `base` (now [x, y]), `preview` and `snapOverride`. A typed object snap word (END, MID, ...) now sets a one-shot override shown as `Endpoint of:`; the next point or pick is taken from the interface's `snap` when its mode matches, otherwise the engine searches the document (`snaps.search`, aperture from `snap.aperture` or 2 percent of the view height; a pick searches the picked object with no aperture). Perpendicular and tangent are resolved by the engine from `snap.handle` and the base point; with no base they are deferred: the provisional point is the pick location, and the same list object the command stored is rewritten in place when the next point (or a second deferred snap, solved as a pair) arrives. Preview resolves a pending deferred point for the cursor and restores it. Pair solving covers circle and arc tangent-tangent (four common tangents), tangent-perpendicular and perpendicular-perpendicular with lines and circles; splines have no evaluator yet and are refused.

`jig.py`: a prompt carries an optional `jig` function of the cursor point (`ctx.point(..., jig=fn)`); `POST /api/docs/{id}/preview` runs it under the document lock and never touches the document. E1's display builder was not present, so `jig.item` builds the display item shape from the contract itself (handle null, `jig: true`, index 7 colour flagged `color7`, ACI 1 to 9 only); swap `entity_item` for the builder when it lands. A selection window with one corner previews its rectangle. Jigs: LINE, CIRCLE (centre radius, diameter, 2P, 3P), ARC (three point, centre, end, continue), PLINE (line, arc, tangent, angle, second point), RECTANG (with fillet, chamfer, rotation, dimensions, centre mode), MOVE and COPY (moved clones, capped at 2000).

Selection: `GET` and `PUT /api/docs/{id}/selection` hold the implied selection; PICKFIRST 0 makes PUT store an empty set; commands already consumed it through `_preselected`. At select prompts `selection` modes set, add, remove act on the pending set, a pick adds the object (ends single-object prompts), a point starts an automatic window (right is Window, left is Crossing, still bounding-box tests). Idle pick adds or replaces by PICKADD.

Grips (`grips.py`): grip sets per kind from B4 8.1 with string ids (`start`, `mid`, `end`, `center`, `q0..q3`, `v3`, `m3`, `c2`, `f2`, ...); modes stretch, move, rotate, scale, mirror, copy, base, reference (`ref`), multifunctional `option` (add_vertex, remove_vertex, convert_arc, convert_line, lengthen with optional `value`, radius), one undo step per request. Rotate, scale, mirror and move apply to the whole implied selection when the hot object is in it; stretch also drags coincident grips of other selected objects. Locked layers are refused. Added `GET /api/docs/{id}/grips`. Fit splines move only the fit point (no fitter exists).

## Clean-room renames · _v0.2.0 (app/doc/service.py, app/routers/docs.py, app/routers/sysvars.py, app/cmd/registry.py)

`DocError` became `DocumentFault` and `CommandSpec` became `CommandEntry` because both collided with type names in the reference. Behaviour, attributes (`message`, `status`) and HTTP mapping are unchanged; no other file used either name. The generic lowercase identifiers from the audit (`state_id`, `next_handle` and similar) were left as ordinary vocabulary.

## Templates, document kinds and the frozen engine · _v0.2.0 (app/doc/templates.py, app/doc/container.py, app/doc/service.py, app/doc/autosave.py, setup/freeze_backend)

`POST /api/docs` takes the Home template ids (`drawing-mm-a3`, `drawing-inch-ansi-b`, `part`, `assembly`, `drawing-sheet`, `surface`, `form`, `graph`) and the plain `metric`, `iso`, `imperial`, `inch`; each sets kind, units, limits and the layout sheet; an unknown id is a 400. The manifest records `kind`; open and recovery read it back and treat a missing or unknown kind as `drawing`. The 3D kinds open in the drafting view until their workspaces land. The freeze puts `app/data` at `app/data` (the kernel record lookup path) and names numpy and ezdxf as hidden imports because nothing imports them yet; without both the frozen selfcheck failed.

Verified: all eight ids answer 200 with their kind and units, `bogus` answers 400, a saved surface document reopens as surface; the frozen engine (135 MB, 215 files, no OCP, build123d or OCCT inside) passes selfcheck and the licence scan.

## Engine core, document core and kernel link · _v0.2.0 (app/main.py, app/core/, app/services/, app/routers/, app/doc/, app/cmd/, app/sysvars/, formcad_engine.py, kernel/)

Routers load from one list, `ROUTERS` in `app/main.py`, as `(module, prefix)` pairs through importlib, so a phase adds a router with one line; route paths inside a module are relative to its prefix. The guard (`core/guard.py`) checks a loopback Host, an Origin allow list and the `X-FormCAD-Token` header; the token is new per start, written to `<data>/session.token` with mode 0600, injected as a meta tag when the engine serves the built interface; `/api/health` is the only open route. The autosave folder is created 0700.

The OpenCascade kernel never loads in this process. `services/kernel.py` finds the worker through `FORMCAD_KERNEL` (a frozen program or a `.py` path), `<data>/kernel/<release>/formcad-kernel`, then the repo's `kernel/venv`; it speaks JSON lines on stdio (`hello`, `shutdown`). OCP exposes no OCCT version constant, so the worker reports the first three parts of the OCP version as the OCCT version and the full OCP version beside it. The install path extracts with the tar `data` filter, requires every file to match `app/data/kernel-licence.json`, refuses extra files and installs nothing on a mismatch; the record ships with `release: null` until formCAD-binaries publishes a build.

The document is a handle-keyed store (handles from 0x100) with an entity kind registry; unknown kinds round-trip untouched in the foreign-data slot. Undo is a change journal of before-images per transaction, not document copies; marks, BEgin/End groups and a 2000-step cap. New drawings without a template follow MEASUREINIT (imperial by default). Typed object snaps that need a picked point answer that a canvas pick is required until the drafting canvas lands; window and crossing selection use bounding boxes until exact hit tests exist. Linetypes whose dash values the spec did not give numerically use our own consistent values.

Verified: selfcheck exits 0; health open, capabilities 401 without the token, 403 for a foreign Origin or Host; websocket refused without a token; the dev worker reports OCCT 8.0.1, OCP 8.0.1.1, build123d 0.13.0; LINE with four inputs makes two lines, save and reopen keep two, U removes both, REDO restores them.
