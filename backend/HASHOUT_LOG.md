Systemic guard: the run token carries the macro's granted folders (`guard.RUN_FILES`, `guard.FILES` context var, copied into a started SCRIPT as `ScriptRun.files`). `barred.args_refusal` refuses, for a macro or an MCP agent, any programmatic argument named path, paths, file, files, filename, folder, dir or out, or ending in _path or _file, unless its value is inside a granted folder (agents: folders listed under `agentFolders` in automation.json, empty by default); the dedicated `formcad_*` file tools are unchanged. `barred.prompt_refusal` stops a typed answer to any free-text prompt whose message mentions a file, folder, path or directory, because prompts carry no file marker. Cost: macros and agents lose file arguments on commands such as INSERT from a file or SCRIPT with a path unless the folder is granted.

## Embedded LISP dialect · _v0.6.0 (lisp/*, cmd/commands/lisp.py, cmd/prompts.py, cmd/runner.py, cmd/lisphook.py)

Built only from the B6 spec as the package `app/lisp/` (types, reader, printer, interp, lib_* for numbers, lists, strings, misc, input, command, entities, selection sets, tables and system variables, session, hooks). The engine never imports OCP or build123d. Values: nil is Python `None`, T and the null symbol are interned symbols, lists are `Cons` cells, integers wrap to 32 bits, reals are floats, entity names carry the handle, selection sets a handle list. 188 names are implemented (14 special forms and 174 functions: the spec list names 175 function tokens but `cdddr` and `load` each appear twice, and `cddddr` was added); the registry holds 189 entries counting the 14 forms.

Evaluation is recursive with a step budget (500 million), a depth cap (100000 user calls), 60 s of running time (time spent waiting for input does not count), a live-object growth cap (9 million blocks, the stand-in for the 5 million cons cells) and a 2 GB output cap; each stops the routine with a message. A routine always runs on its own worker thread with a 512 MB stack, handing `doc.lock` over with the thread (ping-pong, only one side runs at a time), so deep recursion cannot crash a request thread and input functions can wait. A get* call installs a shell run on the command runner whose prompt carries a parse function (`Prompt.parse`, `hint == "raw"`: the spec messages come from the LISP side); `pause` in `command` wraps the open command's generator in a tap and the runner state poll resumes the routine once the user answered. Esc closes the shell and the routine ends with "Function cancelled" (`*error*` runs once, after unwinding). Programmatic evaluation never waits for the user: input functions take pre-supplied answers and return nil when none are left.

Undo: no outer transaction. Every inner command and every direct edit commits its own step; when the routine ends the steps made since it began are merged into one step labelled with the command (or LISP), earliest `before` wins, so U inside a routine still works and one U after it takes back all of it. `entdel` restores only what the same routine deleted.

Safety: file functions go through `lisp/support.py`: folders in `<data>/lisp-settings.json` (key `support`, default `<data>/support`), realpath containment so `..` and symlinks cannot leave, writes only to the first folder for relative names, 64 MiB per file. APPLOAD (any `.lsp` path, case-insensitive; the user chose it) registers the file by name so `(load name)` finds it. Startup files (acad.lsp once, acaddoc.lsp per drawing, then S::STARTUP) are read lazily on the first routine of a drawing from the first support folder only. No network, no shell, no `vla-` or `dos_` names; absent names give "no function definition". Output is buffered by line; the null symbol prints nothing.

Hooks: `runner._tokens` groups a parenthesised token (strings honoured); `_idle` sends `(` and `!` lines to `hooks.run_line` and tries a defined `c:NAME` before the sysvar fallback (built-in commands win, the lookup is off while a routine runs); `_feed` takes an expression as the answer to a prompt (number, string or point as typed text, nil gives no input); `state()` polls a paused routine. `Prompt` gained `parse`. Left open: transparent `'(...)` forms, the `1>` continuation prompt for an unbalanced typed line (an error is shown instead), custom keyword shortcuts that disagree with the runner's own.

## Automation surface: CLI, MCP, control protocol, Python macros, plugins · _v0.6.0 (automation/*, data/sdk/*, routers/{mcp,automation,docquery}.py, cmd/commands/zz_plugins.py, core/guard.py, core/runtime.py, formcad_engine.py, main.py)

MCP is written by FormCAD as plain JSON-RPC, no SDK and no new dependency (R14: the SDK adds about fourteen packages and has no proven frozen stdio). One `Server` class answers both eras: `server/discover` and per-request `_meta` (2026-07-28: `resultType`, `ttlMs`, `cacheScope`, `-32602` for a missing `_meta`, `-32022` with the supported list) and `initialize` plus `notifications/initialized` (2025-11-25 down to 2024-11-05, which echoes the client's version when known). A request without `_meta` is accepted only after `initialize` on the same stdio stream, or on HTTP when `MCP-Protocol-Version` names an older revision; the HTTP route builds a fresh `Server` per POST, so no state crosses requests. The unverified fields were checked against the 2026-07-28 schema this turn: `cacheScope` is `public` or `private`, `ttlMs` a number, `Implementation` has `name`, `title`, `version`. Tools: 22 fixed (`formcad_*`: command line, script, execute, list commands, documents, inspect, query entities, find text, render, selection, cancel, undo, redo, export, display list, variables) plus one `cmd_<id>` per programmatic command form, sorted, cached until a plugin changes the catalogue. Schemas: 17 core commands have typed curated schemas (`automation/forms.py CURATED`), the rest list the argument names read from the execute function's bytecode (works frozen, where source is absent) with `additionalProperties` true and an `inputs` array for typed answers; commands whose forms hide the names behind a helper show `inputs` only (gap). Arguments are validated against the schema by a small checker (types, required, bounds, unknown fields on curated tools), and a refused call is `-32602`; a command that runs and fails is an `isError` result with the engine's message. Hints: draw, view and inquiry tools are non-destructive, modify tools and file overwrites destructive, listed queries read-only; the hints are only hints, nothing relies on them. `--tools core` serves the 22 fixed tools plus the 17 curated ones for clients that cap the tool count.

stdio: `formcad-engine mcp` runs a headless in-process session (`sys.stdout` is swapped to stderr so a stray print cannot corrupt the stream; exit on stdin close). `mcp --connect HOST:PORT|auto` is a bridge: each line is POSTed to the running engine's `/mcp` with the session token (env `FORMCAD_URL` and `FORMCAD_TOKEN`, or `engine.port` and `session.token` in the data folder for `auto`); a refused connection answers "did not run", a lost reply to a `tools/call` answers "may have run, inspect first" and is never resent; `--connect` without a value is a usage error, never a headless fallback; `--launch` is refused. HTTP: one `POST /mcp` behind the existing token, Origin and Host guard; GET and DELETE are 405; `Mcp-Method` and `Mcp-Name` must match the body for the new era (400, `-32020`). Progress and cancellation are not sent: every tool returns before the next message is read.

Control protocol (F2): newline JSON on 127.0.0.1 when started with `--control-port N` (or `FORMCAD_CONTROL_PORT`, 0 picks a port); each request carries the token; the token is a fresh `token_urlsafe(32)` written O_EXCL, mode 0600, to `<data>/control-<port>.token` (stale ones are removed at start); 16 connections, 256 MiB line, 64 queued, 10 minutes idle, 60 seconds per call with `not-run` or `may-have-run` on timeout; a non-JSON-object line gets one error and the connection is closed. The methods are the F2 groups that exist without a window (line, engine, drawing, capture, app, meta); the UI observation, UI action and window screenshot groups belong to the interface and are not served. The same dispatcher is `POST /api/automation/control` behind the HTTP guard.

CLI (F1, `automation/cli.py`): info, convert, run, commands, mcp, perf, sample, plus plugin (seal, list) and macro. Options are parsed by a small parser that rejects unknown and repeated flags and a value starting with a dash unless written `--flag=value` (negative numbers are values); exit 0, 1 (a step failed), 2 (usage). `convert` forces the output type from the extension (pdf, png 2400x1600, svg, dxf with `--dxf-version`, dwg, fcad), refuses OUT equal to IN without `--in-place` (through `samefile`), reads fcad, dxf, dwg and svg. `run` executes `--sample`, `--new` (metric), `--script`, `--script-file`, `--lisp-file`, `--python-macro`, `--command "id {json}"` in the order typed; the placeholder `"last handle"` at any depth becomes the last handle a step returned. The headless session uses the real service singleton with autosave off. `--lisp-file` calls an `appload` or `load` command when one has a programmatic form; the LISP package has no entry yet at the time of writing, so the step fails with a clear message until it does.

Python macros: the client module `formcad` and the host `_host.py` are standard-library-only files in `app/data/sdk/` (bundled by the existing `--add-data app/data`). A macro runs as `python -I _host.py FILE` in a throwaway working folder with a scrubbed environment (PATH only, no HOME, no PYTHON*), stdin closed, output to files and cut at 256 KB, its own session or process group killed on the timeout, rlimits on POSIX (CPU, address space 1 GiB, file size 16 MiB, open files, processes), a Job Object on Windows (kill on close, process count, memory, CPU; written from the documented API and not run here). The host adds an audit hook that blocks writes outside the working folder and granted folders, reads, directory listings and stats outside the interpreter, the SDK, the throwaway folder and granted folders (the macro's own folder is no longer readable unless granted; /proc and /sys never), network other than the engine's loopback port, new processes and native code. This is containment for mistakes and hostile snippets, not a security boundary: the macro still runs as the user, and an audit hook can be bypassed by code that already runs natively, which is why `ctypes` is blocked and why the preferences must say so. Trust is per file: `automation.json` in the data folder stores the sha256 of the source and the grants (network, subprocess, native, folders); an edited file loses trust; the interface shows the source and the hash and passes the hash back when trusting. The macro gets a per-run token (`guard.issue_run_token`) valid only under `/api/docs` and `/api/commands`, revoked when the run ends. The 0.6.0 text said this meant a macro could not enable plugins; the audit showed that false (programmatic `lisp support` plus `pluginenable`), and the round-two fix below is what makes it true: the token is refused on open, save, plot, macro, export, xrefs and import routes, and the runner refuses every command outside the drawing groups and every LISP line for a macro caller. The interpreter is the user's Python (setting `python`, with detection), the engine's own Python when not frozen, and the frozen engine itself through `formcad-engine macro --host FILE` when no interpreter is set.

Plugins: nothing is imported at discovery. Tier one is the entry point group `formcad.plugins` (enabled flag stored with the installed version; a changed version disables it); tier two is `<data>/plugins/<id>/plugin.json` with `id`, `version`, `api`, `entry`, `permissions` and a `files` table of sha256 per file. Enabling stores the manifest hash the user was shown; loading requires every listed file to match, no unlisted code file in the folder, and the stored manifest hash to match. A plugin defines `register(api)`; `api.command` and `api.executes` register through the normal registry (so menu entries, the catalogue and MCP tools follow), names that already exist are refused, a failed register is rolled back, and disabling unregisters the commands (module code already imported stays in memory until restart). Plugin code runs in the engine process because it must register commands there; enabling is therefore the trust decision, and the manager must say so. `formcad-engine plugin seal DIR` writes the hash table. Enabled plugins load when the command modules load (`cmd/commands/zz_plugins.py`, last in import order).

Guard changes: `guard.py` gains run tokens (scoped by path prefix, HTTP only). `docs.py` already owned `/{doc_id}/selection`, so the macro client uses that route; new document routes live in `routers/docquery.py` (entities, variable, summary, export, render).

## Kernel worker operations and 3D documents · _v0.6.0 (kernel/*, solid/*, doc/kinds/solidbody.py, routers/scene.py, cmd/commands/solids.py)

Units: kernel millimetres, document units converted in `solid/work.py` with `param.units.mm_per_unit`; the scene buffer is converted back to document units. Bodies are entities of kind `solidbody` in the model space (name, colour, layer, source, BREP blob id, version, persistent ids, summary, 2D extent, offset), so undo and redo ride the normal transaction. The BREP text and the cached tessellation are content-addressed blobs in `Drawing.blobs`, written to `parts/<id>.brep` and `cache/<id>-d<detail>.mesh` in the `.fcad` zip (only for bodies still present) and read back on load. Blobs are immutable, so an undo only swaps the record; the in-memory dict is not trimmed until save. Worker shapes are cached by (blob, offset) with an LRU of 96 and keyed to the worker serial, so a restarted worker reloads from the blob.

Moving: the generic MOVE calls `SolidBody.move_by`, which accumulates `offset` (document units); the scene adds the offset, the worker bakes it (`transform`) only when a boolean, mass or export needs the shape. Rotate, scale and mirror of solids are not wired into the 2D commands; `SOLIDMOVE` (translate, rotate, scale, matrix) bakes through the worker.

Commands: BOX, CYLINDER, SPHERE, CONE, TORUS, EXTRUDE (closed polyline, circle or region; negative height goes down), MASSPROP, SOLIDMOVE. UNION, SUBTRACT and INTERSECT dispatch by kind inside the existing commands (single-region edits in `boundary.py`): if the first selection holds a solid the solid path runs, otherwise the region path is unchanged. The first solid survives as the result and keeps its handle; the others are erased. Primitives stand on the world Z axis (no 3D UCS yet); `axis` is accepted by the programmatic CYLINDER only.

Mesh: `BRepMesh_IncrementalMesh` with absolute linear deflection `max(0.0008 x bbox diagonal x detail, 0.001 mm)` and angular 0.3 rad (0.4 and 0.5 for coarser detail); per-face nodes, triangle winding flipped for reversed faces, normals from `Poly_Triangulation.ComputeNormals`, edge polylines from `PolygonOnTriangulation` with a `GCPnts_TangentialDeflection` fallback. Bounds: `bounds` defaults to the exact geometry box (`BRepBndLib.AddOptimal` without triangulation) because the triangulation box is enlarged by the deflection (a 100 mm box reported -0.022); the mesh box in the file header is the min and max of the nodes. Volume is reported only for a closed valid solid (`ShapeAnalysis_FreeBounds` finds no free edge and `BRepCheck_Analyzer` is valid), otherwise `volume` is null with a note.

Persistent ids (`solid/ids.py`): one document-wide counter, ids for faces and edges, inherited through the worker history (Modified, Generated, IsDeleted per input face and edge, input order base then tools). Split policy: the first output keeps the id, later outputs get new ids with a `lineage` entry naming the parent; merged faces keep the first input's id; unclaimed outputs get new ids. Ids are kept through transform, subtract and union (checked); a counter burned by an undone operation is never reused.

Files: STEP through XCAF (names, colours, assemblies flattened with locations applied, compounds of solids split to one body each), written as AP214 unless `schema` says ap203 or ap242; IGES through `IGESControl_Reader` under a lock, read only. OPEN, IMPORT and the interchange open route accept `.step .stp .iges .igs`; EXPORT writes `.step`; SAVEAS refuses them. A STEP document is untitled until saved as `.fcad`. The worker moves OpenCascade console text to stderr (stdout carries only protocol lines). Large buffers travel by temporary files named by the engine, never the JSON line; limits: 512 MB input, 256 MB blob, 4 million triangles, 60 s short and 300 s long calls.

Left open: no colour per face from STEP, no TNaming, no fillet or chamfer operation, no 3D UCS, no taper, rotate and scale of solids from the 2D commands, pruning of unreferenced blobs in memory.

## Scripts, aliases, file commands, inquiry and the macro recorder · _v0.6.0 (cmd/script.py, cmd/macro.py, cmd/aliasfile.py, cmd/lisphook.py, cmd/commands/{scripts,macros,aliases,filecmds,inquire,toggles}.py, doc/{audit,compare,count,queries,recover,savecheck}.py, doc/templates.py, doc/service.py, routers/filetools.py, cmd/runner.py, cmd/registry.py, main.py)

Scripts run through the real runner: `cmd/script.py` keeps one `ScriptRun` on the runner, and `state()` drains it (so a script finishes inside the request that started it, and a poll advances a script that waited). Lines go to `runner._submit`, never `submit`, so the recorder does not record a playing script. A blank line is Enter at a prompt and nothing at idle (a repeat of the last command inside a script would be a trap); a trailing space is one Enter; at a free-text prompt the whole line is the text. Own directives: `^C` cancels the running command, `@pick x,y [shift]` picks the object nearest the point (an entity prompt, an object selection, or the selection at idle), `@box x0,y0 x1,y1` selects by window (x1 at or right of x0) or crossing, `@handles h,h` selects by hex handle. Lines starting `(` go to `cmd/lisphook.lisp_line`, the one function pointing at the LISP evaluator. An error in a line pauses the script on that line; RESUME continues with the next line; Esc (cancel) pauses a running script and a second Esc stops it. DELAY is transparent so it works between the inputs of a command; it never sleeps, it sets a wake time and a timer re-enters the script under the document lock. RSCRIPT repeats until cancelled, with a 50 ms gap, or `times` runs in the programmatic form. A script is limited to 4 MB, 200000 lines per file and 2 million lines run in total; only `.scr` files.

Aliases: FormCAD's own alias file is the `.fcalias` text file, `ALIAS, *COMMAND` per line, `;` comments, `[section]` lines ignored, the published `.pgp` layout is read too; lines for external programs are refused with a warning, never run. Limits: 2000 aliases, 32 characters, 256 characters a line, 50 warnings. Only `registry.USER_ALIASES` changes; the last loaded file is remembered in `<data>/aliases.json` and read again when the command modules load (`registry.load_modules` calls `aliasfile.startup`). Command names always beat aliases (`resolve` order is unchanged).

File commands: NEW asks for a template (default QNEWTEMPLATE, `.` for none) and accepts a built-in name, a path, or a name in `<data>/templates/`; a template file is `.fcad`, `.dwt` or `.dxf` and the result is an untitled drawing. QNEW never asks. CLOSE and CLOSEALL ask Yes/No/Cancel when a drawing has changes and close through `runner.later` (a command cannot close the document whose generator is running); the programmatic forms never ask. SAVE (alias QSAVE) refuses while a reference is edited in place (also enforced in `service.save` and `save_foreign`), writes DXF and DWG with the version and binary choice remembered from SAVEAS, and asks "Save anyway" when `savecheck.loss` finds objects the DXF writer drops; the answer is remembered per file and loss. AUDIT lists up to 100 lines, repairs in one undo step, writes `.adt` beside a saved drawing when AUDITCTL is on; generated dimension blocks do not exist in this engine so that repair is absent, and constraint records are checked through their `handles`, `entities`, `objects` or `refs` lists. RECOVER reads a damaged `.fcad` leniently (`doc/recover.py`: bad objects dropped and counted) and then audits and fixes. COMPARE keeps its result on the document (`doc.compare`), matches by full signature (equal handle first), then changed (same handle and kind), 200000 objects, 1000 listed per kind, a grid of at most 8 x 8 for change areas; COMPAREEXPORT recolours copies (current 3, other 1, both 8) and recoloured block copies, but not styles.

Inquiry: LIST, STATUS, TIME, COUNT, COUNTLIST, COUNTTABLE and the program queries (INSPECTDRAWING, QUERYENTITIES, QUERYTEXTS, ANALYZESHAPES, IMPLIEDLOOPS, ANALYZEUSAGE) are commands with typed and programmatic forms, and also routes in `routers/filetools.py`. COUNT reports dynamic-block instances under their base block. Implied loops treat segment ends within the tolerance as one node, exclude every segment at a junction of three or more ends, and report a spur when both ends of one segment meet.

Macro recorder: the runner calls `runner.rec(kind, ...)` at its public input points; the recorder turns them into script lines (typed text, canvas points as `x,y`, picks as `@pick`, canvas selections as `@box` or `@handles`, cancel as `^C`, programmatic commands as `name {json}`). Python output is `import formcad`, `doc.send(line)` per typed line and `doc.script(marker)` for the markers. Playing a `.py` macro goes through `automation/macros.run` on a thread, never under the document lock; macros this engine saved are trusted by file hash, any other file needs the trust step of the automation module.

Also added: TRANSPARENCYDISPLAY, QPMODE, SELECTIONCYCLING, ISODRAFT, ISOPLANE and DSETTINGS (typed loop and programmatic form). Left open: portable fonts option of SAVEAS, the Template option of LAYOUT stays with F6.

## Drafting constraints, parameters and the Phase 15 sketch · _v0.6.0 (param/*, solve/constraints.py, solve/model.py, doc/tables.py, doc/kinds/constrainthook.py, display/constraint_marks.py, display/state.py, cmd/constraint_flow.py, cmd/commands/constraints_*.py, routers/constraints.py, main.py)

Storage is three new drawing tables (`TABLE_NAMES`): `constraints` (one record per relation or dimension: id, kind, refs `[handle, part]`, sketch, dimension label, expression, value, driving flag, solver context), `parameters` (user parameters: name, expression, unit, comment) and `sketches` (name, plane, entity handles, construction handles). Tables give undo, redo, save, reopen, autosave and the DXF private records for free, and are read through `d.table_set`. Settings (tolerances, inference, bar and dimension display with per-object exceptions) are one header value `CONSTRAINTSETTINGS`. Dimension names (d1, ang1, rad1, dia1) are unique across the document and share one namespace with user parameters; names equal to units, functions or `pi`, `e`, `tau` are reserved.

Solver changes (additive): `Sketch.restore` (re-enter a stored constraint with its id and context), `Sketch.measure` (the value a dimension would have now), `Sketch.add` takes `cid` and `ctx`, per-parameter weights (`set_param_weight`), and Fix now keeps its target in the constraint context (`pt`, `base`) so a reopened drawing keeps its fixed places. Sign contexts (distance direction, tangent side, symmetric pairing) are stored in the record and passed back on every rebuild.

The solver is rebuilt from the records on every operation, only for the connected component the operation touches (sketch members are always loaded whole). Adding a constraint is a trial: the constraint is restored into the throwaway solver, solved and analysed; only if it is neither conflicting nor redundant are records and geometry written. A refusal writes nothing and carries an explanation (`param/explain.py`): for a conflict the set is reduced by deletion (drop each constraint, keep the drop when the rest is still unsolvable from the start or two jittered starts; budget 2 s, `minimal` false when the budget ran out); for redundancy the set is the new constraint plus the earlier ones its Jacobian row depends on, reduced the same way by rank. Over-defining by a parameter change (a new value that cannot be met) is refused the same way after a stepped retry in 8 increments. `force` keeps a redundant (not conflicting) constraint; the status then reads over defined.

Expressions (`param/expr.py`): numbers, names, quoted names `'d1@Sketch1'`, `name@sketch`, `+ - * / ^`, unary minus, functions (sqrt, abs, trig in degrees, min, max, pow, hypot, ln, log, exp, round, floor, ceil, sign, atan2), `pi`, and unit literals (`25mm`, `3 in`, `90 deg`, `0.5 rad`) converted to drawing units (from INSUNITS, else mm or inch) and degrees. A parameter with a unit reads a plain number in that unit. Cycles are found by the lookup stack and named ("Circular reference: a -> b -> a"). A driving dimension cannot use a reference (driven) dimension; user parameters can. Deleting a parameter or dimension that others use is refused ("x is used by y"); a dimension's own name cannot be deleted from PARAMETERS. Rename rewrites whole-name tokens only.

Edit hook (`doc/kinds/constrainthook.py`, priority 60, after the command and before dimension follow): objects erased leave drafting constraints removed with a count, and sketch constraints marked dangling (kept, not solved, restored by undo). Edited constrained geometry is re-solved with the changed parameters weighted 1e8, so a grip drag holds the dragged point and MOVE holds the moved object while partners follow. A Fix whose fixed place was itself edited takes the new place (the user moved it on purpose). If the edit cannot be satisfied it is reverted and "Constraints could not be satisfied" is printed. Operations of this module set `tx.constraint_done` so the hook skips them. CONSTRAINTINFER (the existing system variable) infers coincident, horizontal, vertical, perpendicular and tangent from exact geometry of new objects; parallel inference is not done because snaps are not visible to a hook.

Polylines are chains of solver lines with implicit joints, referenced as `v<n>` and `s<n>` counting from 0; splines, block references, text and others answer "<kind> objects cannot be constrained." Polyline `whole` is refused for Fix (name a vertex). Arcs: tangent is between full circles (solver limit, S1). Angular on two lines accepts up to 180 degrees.

Display: `display/constraint_marks.py` wraps the circle, arc, point, polyline and ellipse builders and, through `install()`, the line fast path, appending one `cbar` prim per constrained object: `{t, state under|fully|over|none, dof, rgb, glyphs[{id,k,p,slot,dangling}], dims[{id,name,expr,value,driving,kind,p}], sketch{name,status,dof}}`. The line path is not a builder so `install()` (called when the constraints router imports) replaces `state.line_entry`; the one Edit in `state.py` only registers the module. Constraint operations touch every entity of the affected component so cached display entries rebuild. Status data is cached per document revision.

Not done: live solve during a grip drag preview (the solve runs at release), midpoint and coradial as named relations (use Coincident with a Fix or Concentric plus Equal), dimension text style, driving a dimension from another sketch except by name, splines, Fully Define Sketch (AUTOCONSTRAIN covers relations, not dimensions).

## Display list and text pipeline · _v0.3.0 (app/display/, app/text/, app/routers/display.py, app/data/fonts/formcad-stroke.json)

`GET /api/docs/{id}/display?since=<rev>&space=<model|layout name>` answers the contract item shape from a per document, per space `DisplayState` (display/state.py) that keeps one JSON fragment per entity and joins fragments into the response, so a full response is a string join and a delta never re-encodes untouched items. `since` omitted, older than the first build's floor (newest layer, linetype, text style or header revision seen when the state was first built) or newer than the document revision gives `full: true`; otherwise only items whose fragment changed after `since` come back, plus `removed` handles (erased, moved to another space, hidden by layer, visibility or isolate, or no longer drawable). Detection uses `ent_rev`, `removed_rev` and `space_rev`; a change to LTSCALE, LWDEFAULT, PDMODE, PDSIZE, FILLMODE, TEXTFILL, FONTALT, FONTFALLBACK, the linetype or text style tables or the session hidden set rebuilds every item and compares fragments; a layer change rebuilds only that layer's items (and block users); block edits rebuild the inserts that use the block. When nothing bumped `rev` but the display changed, the state calls `doc.bump("display")` so `since` stays truthful. `order` is a sparse key (1024 apart, appended items get last plus 1024, restored items get the midpoint) so erasing one item never renumbers its neighbours; only a draw order change renumbers. Line items use a format string fast path (a test proved it equals the generic builder byte for field).

Resolved properties: index and true colours (`#RRGGBB` strings or `[r,g,b]`) through the 256 entry index table (palette.py, generated by hue, five brightness levels 255, 165, 127, 76, 38 and the half saturation variants; 8 and 9 follow the spec values), ByLayer and ByBlock (block parents), `color7` for index 7 reached directly, by layer or by block; lineweight ByLayer, ByBlock, Default (LWDEFAULT, out of range falls back to 0.25), always sent resolved with the top level `lwdisplay` flag so the renderer toggles without a refetch; transparency capped at 90 percent as 0 to 0.9, top level `trdisplay`; linetype pattern in drawing units with positive dash, negative gap, zero dot (text and shape elements dropped, equal sign runs merged), `scale` = LTSCALE times the entity's own scale times the enclosing insert scales (CELTSCALE only seeds the entity's own scale when a command creates it, which `Context.stamp` already does); continuous patterns send `lt: null`; `lt.gen` marks polylines with linetype generation. PSLTSCALE has no effect until viewports exist.

Extra fields beyond the contract, all optional for the renderer: `color7`, prim `c` (RGB) and `c7` for per run colours from `\C` and `\c` (index colours are converted before sending), part level `color`, `color7`, `lw`, `lt` inside insert and dimension block compounds, point `rel` (percent of view height when PDSIZE is zero or negative) and `rot`, layer summary `color7` and `plot`, the top level `lwdisplay` and `trdisplay`. Polyline widths come as `fill` prims with one ring per sub segment (non zero fill). Hatch: solid fill rings, or parallel line `pl` prims from a small pattern table (ANSI31 family, LINE, NET, ANGLE, STEEL; unknown names use 45 degrees); gradients draw solid; full pattern libraries are not built. Dimensions draw only their geometry block (when `block` names one) and otherwise send an empty compound with bounds. Block arrays honour `rows`, `cols`, `row_spacing`, `col_spacing` keys if present.

System folders: macOS `/System/Library/Fonts`, `Supplemental`, `/Library/Fonts`, `~/Library/Fonts`; Windows `%WINDIR%\Fonts` and the per user folder; Linux `/usr/share/fonts`, `/usr/local/share/fonts`, `~/.fonts`, XDG data folders; plus `<data>/fonts` and `FORMCAD_FONTS`. Outlines come from fontTools 4.68.0 (MIT) flattened at 0.0007 of cap height; text height equals cap height. Outline glyphs are triangulated once per face and character (ear clipping with hole bridging, `tri.py`, original code) and become `tri` prims when TEXTFILL is on, closed `pl` outlines when off; stroke glyphs become `pl` prims. The default stroke font is an original design (`formcad-stroke.json`, ASCII plus degree, plus-minus, diameter and bullet on a 6 by 8 grid, Apache-2.0).
