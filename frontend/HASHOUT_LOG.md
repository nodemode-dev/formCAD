## Properties, Quick Properties, QuickCalc, Find, Quick Select, array bar · _v0.4.0 (src/ui/panels/{properties-panel,prop-rows,props-kinds,row-factory,property-store,selection-bus,quick-props,quickcalc-panel,find-dialog,quick-select-dialog,quick-select-model,array-bar,engine-run,poly-area}.ts, ui/shell-part3.ts, styles/properties.css, main.ts, index.html, io/api.ts, ui/menu-spec.ts, ui/shell-part2.ts, ui/icons.ts, canvas/interact/controller.ts and menus.ts)

Selection source: the interaction layer now publishes `formcad:selection {doc, handles}` from its frame loop whenever the selected set changes, and accepts `formcad:set-selection {handles, mode?, commit?}` (commit false only syncs the canvas, used when the engine announces a selection change, for example after FIND). `selection-bus.ts` is the single reader and writer for panels; `property-store.ts` fetches `GET /properties` once per selection or revision change (one rAF, stale answers dropped, own edits skip the echo of their revision) and every consumer paints from it. Rows are built once per panel from `RowDef` lists in `props-kinds.ts` and patched with `setText`, `setHidden`, `setValue` and an in-place option patcher; per-kind sections exist for every kind up front and are only shown or hidden (a kind seen for the first time without a section gets one once). Mixed selections show one section per kind present and the type selector filters the palette view only (it does not change the canvas selection); shared values show, differing values show `*VARIES*` as a placeholder or selected label. Edits go to `PUT /properties` (one undo step each); derived rows (line Length and Angle, circle Circumference and Area, polyline Area) are translated to the engine fields (`end`, `radius`) on the client and are refused with a message unless the geometry is uniform. A point field that varies disables its X and Y rows because the route reports variation per field, not per axis. Nothing selected shows the current settings, written through the sysvars store (CECOLOR, CLAYER, CELTYPE, CELTSCALE, CELWEIGHT, THICKNESS, TEXTSTYLE, DIMSTYLE, CMLEADERSTYLE, CTABLESTYLE, TEXTSIZE), with name lists from the snapshot tables. Quick Properties is a floating box in the stage, placed 28 px from the last pointer position when the selection changes, shown when QPMODE is above 0, no command runs and the selection matches the payload; a status bar toggle (`toggle-quickprops`) flips the sign of QPMODE. QuickCalc is a dock panel (Mod+8 toggles, focuses the field); evaluation, variables and unit conversion use `POST /api/calc`, drawing picks run the engine `quickcalc.pick` command through the normal command line path and read the answer from the last history line when the command goes idle; history (100, 20 shown through 20 prebuilt rows), variables (50) and `ans` persist under `formCAD.quickcalc`. Find and Replace calls `POST /find` (find selects the matches, Replace All replaces on the engine, Replace rewrites one text, multiline text or dimension object through `PUT /properties` because the route has no per-object replace). Quick Select has no engine route: it reads `GET /snapshot` (raw entity records), keeps the objects present in the current display, and sets the selection from the client (include, exclude, append, wildcard, numeric compare with tolerance). The array row lives in the empty `.cv-options` bar and appears when every selected object is an associative array; fields are the per-shape rows of the properties route and Edit Array starts ARRAYEDIT.

Shell wiring: `shell-part3.ts` registers the commands before the panels (the palette context menu resolves ids when it is built). Menu ids: `open-properties` (Modify), `open-quick-select` (Edit, Tools), `open-find` (Edit, idle context menu), `win-quickcalc` (Tools, Window, Mod+8), `toggle-quickprops` (Window), `deselect-all`; `win-properties` keeps Mod+1 and now toggles the dock panel through `formcad:ui` actions `panel:toggle:<id>` and `panel:reveal:<id>` handled in `shell-part2.ts` (toggle hides the dock when the panel is already in view, otherwise reveals it). The engine commands `cal`, `find` and `qselect` are no longer menu entries; typing them still reaches the engine. Three icons were added (`calculator`, `quickSelect`, `quickProps`).

Verified (production build served by the engine, Chromium 1440 by 900, software GL, engine on 8291 and a private data folder because 8290 and 5290 were taken by another agent's processes): typecheck and build pass; `arrays-groups-props.fcad` line selected, layer then colour changed in the palette and read back from `GET /display` (layer Groups, colour red), two undo steps restore both, the palette follows; line plus text selected shows `*VARIES*` on Layer, type selector lists All, Line, Text and narrows to Text; ten real canvas selection changes added or removed 0 elements anywhere in the document; `2*pi` gives 6.2831853072 with history, an error echo, a variable `w = 3+4`, `w*2 = 14`, 25.4 mm = 1 in, a Distance pick from two canvas clicks; `text.fcad` Find for Line finds 8 occurrences in 7 objects and selects them, Replace changes one object, Replace All changes the rest, two undos restore the text, Zoom to changes the view; Quick Select Circle radius 4 selects 20 of 27 circles, exclude on layer Arrays selects the other 77 objects, a wildcard with append gives the union; a rectangular array 4 by 2 edited to 6 columns from the bar becomes 12 items and one undo returns 8; Quick Properties edits a line length to 50 and its close button turns QPMODE off; Mod+1 hides and shows the dock; Modify > Properties reveals the panel. Known limits: ArrayBar and kind rows read per-field variation (X and Y vary together); each enhanced select adds its own popup node to the overlay root, so the palette adds about 40 hidden popups (the existing dropdown design); the Properties palette `My` tab is a disabled placeholder as in the spec; Quick Select reads the whole snapshot, so a very large drawing pays one full fetch per opening.

Renames (canvas/interact): `SnapHit` is now `SnapCandidate`, `DynBox` is now `InputField`, `GripMode` is now `GripAction`, `PathKind` is now `TrackPathType`; behavior unchanged.

## Dialogs and editors · _v0.4.0 (src/ui/dialogs/, src/ui/panels/mtext-*.ts, styles/u2.css, io/api.ts, command-line.ts, shell-part1.ts, main.ts, index.html; engine routers/uistyle.py)

Interactive starts of HATCH, GRADIENT, HATCHEDIT, STYLE, DIMSTYLE, TABLESTYLE, MLEADERSTYLE and TEXTEDIT go through `interceptCommand(name)` (`ui/dialogs/intercept.ts`), called in `runEngine` and in the command line `submit` and `runCommand` for a bare word only; a hit opens a dialog built once and the engine command never starts. Hyphen forms, options and `POST /command` keep the engine behaviour; the hatch family honours HPDLGMODE. MTEXT is not intercepted: the engine runs its corner prompts on the canvas and the editor opens when the state is `mtext` waiting for text (`GET /mtext` pending gives the box), commits through `POST /mtext`, and Escape cancels the command. Hatch boundary picking drives the engine: the dialog closes, `hatchpick` runs with the canvas clicks, the dialog reopens and reads the picks with `hatchpick {}`; creation passes `picked: true`. The multiline editor is a contenteditable of flat `<p>` and span runs mapped to the code string by `mtext-codes.ts`; format commands go through a paragraph model and patch only the paragraphs, typing is the browser's own (0 elements added outside the editable over 20 characters). Dimension style preview is `POST /api/docs/{id}/ui/dimstyle-preview`, which builds an unsaved dimension whose overrides are the working variables; pattern swatches come from `GET /api/ui/patterns` (segments from `hatchfill.pattern_segments`). The app's number fields swallow `input` events, so previews update on change, not per keystroke. `patchList` does not call `update` for a node it just created; list rows in the managers paint inside `create` too.

## Draw integration · _v0.3.0 (src/ui/draw-rail.ts, ui/menu-spec.ts, ui/shell-part1.ts, ui/icons.ts, canvas/build.ts, canvas/types.ts, canvas/interact/gripper.ts, canvas/mount.ts, styles/interact.css, main.ts)

Grips: the interaction layer now uses `items[].grips` from the display list directly; the `GET /grips` lookup, its per item cache and the `dirty` flag in `gripper.ts` were removed. The engine emits the same string ids the `/grip` route reads (`start`, `mid`, `end`, ...). `api.gripSets` stays in `io/api.ts` as an unused client method. Locked-layer objects now show grips and the engine refuses the edit with its message.

Wipeout: masking moved from `item.kind === 'wipeout'` (which also painted the frame in the background colour) to the prim flag. A `fill` prim with `mask: true` is built in its own batch segment (`split()` before and after) with flag 2 (background colour), and an item that carries one draws its prims first and its frame geometry after, so the frame stays visible and later items draw on top. Both WebGL2 and the Canvas 2D fallback read the same batches. FILLMODE does not affect a mask. The mask also hides the grid because the scene canvas sits above the background canvas.

Menus: engine commands without an `option` (every Draw item and the tool rail) now post `{text: <name>}` to `/input` (`api.sendInput`), the same path as typing, so each command starts interactively and prompts; `/command` stays for items with an `option` (zoom, pan, and so on). Break Line was added to the Draw menu. View menu items `ViewCube` and `UCS Icon` are the registered canvas commands `toggle-viewcube` and `toggle-ucs-icon` (labels shortened to the menu names); the engine commands `viewcube` and `ucsicon` do not exist. Draw items for commands the engine does not have yet (Region, Boundary, Hatch, Gradient, Table, Multiline Text, Single Line Text, Block, Define Attributes) still answer "Unknown command" and belong to later phases.

Tool rail: `draw-rail.ts` fills the empty `.cv-rail` once at shell mount with 23 icon buttons in five groups (lines, shapes, curves and marks, points, annotations of geometry), each a `data-cmd="x:<name>"` button so the existing delegated click in `app.ts` runs the same registered command as the menu (a second click listener would have started every command twice); disabled with no document, titles patched in place. Thirteen new inline `currentColor` icons were added to `icons.ts` (`xline ray mline poly3d donut solid2d helix revcloud wipeout divide centerMark centerLine breakLine`). Variants (arc forms, circle forms) live in the menu only.

Dynamic input boxes: `.cv-dyn-value` min width is 9ch so a growing number no longer reflows the box beside it (it was the only non input layout shift left, 2e-5 per move).

Verified (Chromium 1440 by 900, engine 8290, Vite 5290, software GL): typecheck and build pass; every Draw item and rail icon starts its engine command; one of every Draw command drawn through menus, rail, typing and canvas clicks with snaps, the new object read back from `GET /display` for each; grip drag of a LINE end moves only p2 and undo restores the geometry exactly. Under CPU 4x, 150 ms latency and 1.6 Mbit/s with `draw-all-part1.fcad`: app-ready after 13.3 s, layout shift 0 after ready, 0 elements added or removed over 3 s idle and over a LINE with 20 pointer moves outside the history strip. Pan, 120 frames of middle drag, software GL, 2 cores: draw-all-part1 median 29.5 ms, p95 38.8, max 45.4 (CPU 4x: 56.4, 72.3, 85.7); lines-100k median 243 ms, p95 309, max 408 (CPU 4x: 385, 447, 497). ## Canvas interaction · _v0.3.0 (src/canvas/interact/, styles/interact.css, canvas types and renderer, io/api.ts, command-line.ts, status.ts)

`attachInteraction(canvas, host)` (called from `canvas/mount.ts`) builds one `Interaction` that turns pointer, keys and the engine command state into canvas input. Engine state arrives from `formcad:command-state` and a new `formcad:cmdline-applied` (the command line dispatches it from `apply`, so typed input is seen too); a new `formcad:cmdline-text` says the typed text changed (dynamic input reads the command line input, which stays the single source of truth). Point prompts (`expect` point, distance, angle) resolve every frame through the spec order: running object snap (computed in TypeScript from exact `geom` of items near the cursor via a new `CanvasApi.itemsIn`), else grid or isometric lattice snap, else tracking paths (polar with POLARANG, POLARADDANG and POLARMODE, acquired points after a 0.4 s rest, extension and parallel, crossings of two paths or a path and an object, PolarSnap steps), else ortho (Shift inverts, isometric plane axes). The result goes out as `{point, snap}`; a typed bare number at a point prompt is direct distance along the sliding path or rubber band; dynamic input text `d<a` or `x,y` is rewritten to `@d<<a` or `@x,y` before the command line submits it. `/preview` is called once per frame with a single request in flight and stale answers dropped; prompts without a jig draw a line from `base`. Selection: pick box picks topmost by draw order, window and crossing from drag or two clicks (PICKDRAG), PICKADD and Shift, hover preview (SELECTIONPREVIEW), cycling badge and list (SELECTIONCYCLING) and Shift+Space stepping; at idle changes are mirrored with `PUT /selection`, at an engine selection prompt they go out as `{selection}` and entity prompts get `{pick}`. Grips: engine grip ids come from `GET /grips` (E1 display grips use list indices that do not match E2 ids, so the display grips only give positions), drag or click-click stretch with live `POST /grip {preview}`, Space or Enter cycles stretch, move, rotate, scale, mirror, Ctrl collects copies committed as one undo step, right-click grip menu runs the engine options. The dynamic input tooltip, options list, cycling badge and context menus are DOM built once and patched; tracking tips, snap markers, grips and boxes use the existing canvas overlays. F1's LTSCALE factor in the renderer was removed because the display list already folds it into `lt.scale`. The status bar coordinate readout now formats with LUNITS and LUPREC.

## Drafting renderer · _v0.3.0 (src/canvas/, styles/canvas.css, io/api.ts, main.ts, index.html)

`mountCanvas(host, deps)` builds three canvases once (background and grid, WebGL2 scene, overlays and cursor) and patches them: display items are chunked by draw order, each chunk holds float32 vertices relative to its own origin in three batches (triangles, hairlines, instanced wide quads), and only chunks whose items changed rebuild. Curves tessellate in TypeScript to half a pixel at the finest zoom of a power-of-two band; band-sensitive chunks rebuild when the band changes. Above 8000 items chunks build only the visible area plus a margin. Colour 7 and wipeout masks are shader flags so theme changes cost nothing. Canvas 2D paints the same batches when WebGL2 is unavailable. Picking uses an own packed R-tree. The cube, UCS icon and their menus are painted on the top canvas and take pointer events exclusively; the system cursor is hidden over the canvas unless the preference keeps it. Measured on software GL: 100k lines pan and zoom median 17 to 83 ms depending on how much is visible, canvas nodes created once, CLS from the canvas 0. The engine display route was stubbed outside the repo while E1 finished; the contract shape is what the code reads.

## Exit handshake, keystroke lists and renames · _v0.2.0 (src/ui/exit-guard.ts, shell-part1.ts, titlebar-tools.ts, dropdown.ts, info-dialogs.ts, prefs.ts, three style files)

The desktop shell blocks close and quit and emits `formcad://exit-requested`; `exit-guard.ts` answers it with the existing Unsaved Changes dialog (Apply to All covers several dirty documents), then calls `confirm_exit` with `cancel` true only when the user backed out. No dirty document means no dialog and an immediate exit. The listener is registered before the pending-opens drain because that drain is what lets Rust start asking. The title bar command search is now a fixed pool of 8 slots, the dropdown keeps one keyed row per option and group heading and filters by `hidden`, and the command reference uses `patchList`, so typing changes text, hidden state and order only; `[hidden]` rules were added where `display: flex` overrode the attribute. `SaveFormat` became `FileSaveKind` to stay clear of a reference type name.

## Family shell, preferences, command line and dock · _v0.2.0 (index.html, vite.config.ts, src/app.ts, src/main.ts, src/ui/, src/io/, src/styles/)

`app.ts` is the composition root: `mountShell()` builds the shell template once and returns every host element; `onShellMounted` and `onCapabilities` let sections register without editing `startApp`. `shell-part1.ts` registers the title bar, menus, tabs, Home and status bar; `shell-part2.ts` registers Preferences, the palette, the command line and the dock; each is one import in `main.ts`. `onCapabilities` registers at module load so the status bar never shows "Engine offline" before the first answer.

Menu items that are engine commands run `POST /api/docs/{id}/command` and show the engine's answer; nothing in the menus is a dead item. Drafting toggles in the status bar read and write system variables (AUTOSNAP bits 8 and 16 for polar and tracking, OSMODE bit 16384 for running snaps) and follow `sysvar` events; engine variables are the source of truth for drafting options, so the preference store keeps only interface settings. Edit shortcuts are left to a focused text field. The command palette key reads `Shift+Mod+P` because `comboOf` orders modifiers Alt, Shift, Mod.

The dev server injects the token meta by reading the engine's token file and stamps the header on proxied requests; the built interface gets the meta from the engine. Font preloads point at the dev paths and fall back to the CSS imports in the build.

Removed from the formvis carry-over: user skins, favourite themes, the dock-boot script and the remembered-values history; they belong to the image editor.

Verified: typecheck and build pass for each part; the built interface mounts in headless Chrome with no console errors.
