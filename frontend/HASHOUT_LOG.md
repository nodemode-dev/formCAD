# HASHOUT_LOG · interface (frontend/)

Living record of decisions and removed context for the interface, newest first. Read before editing.

## Graph editor canvas, Phase 23, v0.9.0 (graph/*, styles/graph.css, io/events.ts, ui/menu-spec.ts, main.ts, index.html)

Rendering: nodes are DOM, wires are one SVG path per wire, both inside one world element moved by a single transform (pan and zoom write one style value per frame; the dot grid is a separate element moved by transform). DOM nodes keep text, widgets (U12 mounts real inputs) and hit testing native; SVG gives per-wire classes for item, list and tree styles; Canvas 2D was rejected because widgets and focus would need a second DOM layer. Port and wire positions are computed from the model (fixed row heights), never measured, so no layout reads happen on edits. Nodes are positioned with left and top and use `content-visibility: auto`, port dots sit inside the node box (paint containment clips outside it). `will-change: transform` on the world was removed: with 500 nodes it made layerization cost about 25 ms per frame against about 4 ms without.

Patching: records are immutable; the canvas keeps a node view per id and re-patches only views whose record object changed, wires whose endpoints changed, and states whose object changed. A node's class is written once per change (one DOM mutation). Measured: slider change on a 4 node graph under CPU 4x and 150 ms, 1.6 Mbit/s: 0 child nodes added or removed, 1 attribute mutation (the Divide node leaving its warning), layout shift 0.00008 for the whole session including opening the graph.

Engine contract: every edit is a whole-definition PUT (`live` coalesces to one undo step); undo and redo arrive as a `graph` event with reason `definition` and the canvas diffs and patches. A solve never blanks nodes at once: stale marks and busy marks appear only after 250 ms. Cycle and kind checks run in the interface for feedback; the engine stays the authority and a refused PUT reloads the definition.

Pan frames with 500 nodes and 1000 wires (headless software raster, machine load about 10): pan 32 ms average, zoom 21 ms, single node drag 45 ms (long tasks remain on drag, layerization of the paint artifact); at CPU 4x pan 175 ms. Idle floor is 16.7 ms. Known gap: drag at this size is not 60 fps; per-node chunk count (clips from text overflow) is the next thing to cut.

## Sheet metal interface, Phase 22, v0.9.0 (sheet/*, styles/sheet.css, part/fields.ts, part/feature-editor.ts, part/kinds.ts, draw/palette.ts, draw/runtime.ts, view3d/viewport.ts, ui/draw-rail.ts, ui/menu-spec.ts, ui/icons.ts, styles/tokens.css, styles/part.css, main.ts, index.html)

Feature panels stay schema driven. The nine sheet metal types come from the registry (group `sheetmetal`) and open through the existing `FeatureEditor`; `part/kinds.ts` only adds their icons and `sm-*` commands (rail group, Part > Sheet Metal submenu). What the generic panel could not say is added in `part/fields.ts`: an enum whose default is null gets a first option "From the sheet metal rule" and reads back null (the per-bend overrides of jog, sketched bend and flanges); `showWhen` hides K, allowance, deduction, table, backup K, width, offsets, hem gap and teardrop angle by the method or mode chosen, and the relief ratio and depth when the type is none; readable words for the enum values. `sheet/bend-field.ts` replaces the raw JSON box of bend relief (`bends`) and corner relief (`corners`) with a checkbox list and a pair list over the engine bend records (rows patched in place). The panel footer was hidden under the gumball bar at 900 px height (the bar never moved); `.pp` now ends 38 px higher.

Flat pattern. `sheet/store.ts` reads `GET /sheetmetal/flat`, `/flat/props` and `/bends` on doc events (debounced) and writes `PUT /flat`; it never computes geometry. `FlatLayer` is a ViewLayer built once: a fill mesh, an outline and two dashed bend line objects (up and down colours from the tokens `--sm-bend-up`, `--sm-bend-down`, the blank tinted with the accent), geometries swapped only when a signature of the flat data changes, labels drawn on the overlay (direction, angle, radius). Toggling hides the body group through `Viewport3D.setBodiesHidden` (also dropped from the fit bounds), looks from +Z, fits, and refolding restores the saved camera; no container, canvas or toolbar node is created or removed. Measured under CPU 4x, 150 ms, 1.6 Mbit/s: toggle on, refold, cut list reveal and dialog open all give layout shift 0 and 0 nodes lost; the first open of a dialog or panel adds its rows inside the reserved box.

Rule editor. The rule lives on the root feature (`base_flange` or `convert_sheet`), so the dialog edits that feature's params through `part.edit` and the tree rebuilds. The live BA, BD, K, neutral radius and setback for 90 degrees are a display mirror of `bend.py` for the three closed forms (method table shows the per bend values the engine recorded, listed under the dialog). The mirror matches the engine to 1e-5 on the R20 channel (BA 6.09469, BD 3.90531). Fields for unused methods stay in place and dim, so nothing moves.

Bend tables. The editor reads and writes `/sheetmetal/tables`; shipped and built in tables are read only (Copy makes a document table); a table without a source text is not saved from the dialog (the engine allows it; R20 asks for a source per value).

Cut list is a dock panel (`sm-cutlist`) with the sheet facts and the bend rows; the flat DXF dialog offers the bending and cutting profiles, version and bend notes, then the normal path dialog, and posts `POST /sheetmetal/flat/export`. Flat views are a tile in the drawing view tools: the engine route `POST /drawviews` drops `flat` (the model has no such field), so the tool creates the base view and then PATCHes `changes.flat`. The 3D toolbar gets a separator and three buttons appended to `.pt-tools3d` (flat pattern, rule, cut list).

## Graph widgets, palette, bake, optimizer, preview, v0.9.0 (graphx/*, styles/graphx.css, ui/icons.ts, ui/settings-dialog.ts, main.ts, index.html)

Everything registers from `graphx/register.ts`, after `graph/register.ts`. It uses only the public surface of `graph/` (`registerNodeWidget`, `registerNodeIcons`, `graphBus`, `graphEditor` with its `store`), plus `graphEditor.store.apply/flush/ensureCatalogue/refreshList/open`, which the editor class already exposes. The head bar of the editor gets one button group inserted before `.gx-grow` and two side panels appended to `.gx-root`; no U11 file was edited.

Widgets. Each factory builds its DOM once in `host` and `update` only patches (value text, a `--gp-fill` custom property, hidden flags, text of a `pre`). Persistent data is `{type, tree: {"{0}": [...]}}` written through `ctx.edit`. The slider drag and the Enter or blur of the typed value are the only writers; a drag sends `live: true` until release and then one final write, so the document holds one undo step per drag (checked: one undo returns the slider and the display). Typing does not write per key, only on Enter or blur, so a run of live edits can never be left open. Min, max, step, decimals and whole numbers sit behind the gear in a Dialog (engine clamps and snaps; the widget applies the same rule so the thumb never waits for the solve). Widgets stop pointerdown, keydown and dblclick so the canvas does not drag or delete the node under them; wheel is stopped only inside `.is-scroll` areas. The panel decides between text editing and tree display by whether a wire reaches its input (`graphEditor.record()`), re-checked on wire events. The button writes true, waits for the engine `solved` event of this graph (4 s cap), writes false: two document edits per press, by design of the engine node.

Palette. One `aside` built once; sections and items go through `patchList` keyed by category and type id, rebuilt only when the catalogue id list changes (plugin enable or disable). Category icons are drawn in `ui/icons.ts` as `gc*` entries (no icon library); categories without an entry fall back to `graph`. Drag sets `application/x-formcad-node`; double click and Enter add at the view centre.

Preview. `GraphPreviewLayer` is a `ViewLayer` with its own group and one slot per preview body (mesh, line segments, points, each with preallocated attributes). A solve fetches `/preview` once (30 ms debounce, one in flight), parses with the existing scene parser and copies into the slot buffers; a buffer is replaced only when the new data exceeds its capacity (power of two). Checked under CPU 4x plus 150 ms network: the group and every slot keep their uuids across a 12 step slider drag, `created` stays 2 while `patched` grows. The parser drops body flags and the node of each body, so the layer reads the record table and the meta JSON itself (point flag, selected flag, `node`). Selection highlight swaps the three materials of a slot; it follows `graphBus` selection and the server selected flag. The viewport only draws in its 3D mode: closing the graph workspace enters 3D when the layer has geometry, and the first preview frames the camera once when the document has no bodies.

Optimizer. The panel posts `commit: false` and applies the best values itself by writing the slider `value` persistent data through `store.apply` (one undo step), so Apply best is an explicit user action. Progress comes from the `graph` events with reason `optimize` and a 400 ms poll of the job; the convergence chart is one SVG path, its `d` patched per update; the history of the job result replaces the live trace when the job ends.

Bake dialog lists nodes whose catalogue outputs have geometry kinds, with item counts from the solved state; layer is free text over a datalist of document layers, colour is by layer unless unchecked. Run headless takes the open graph (definition fetched from the engine) or a `.graph` path; import and export go through `pickPath`. Plugin node types are the catalogue entries whose id contains a slash, listed under the Plugins settings section.

Known and not mine: `.gx-stat` in the editor head changes width with its text and is the only layout shift measured (4e-5); the global select enhancer turns every `select` into a button plus overlay list, so widget selects keep their class on both.

## Drawings from 3D, v0.8.0 (draw/*, styles/draw.css, canvas/interact/menu-extra.ts, canvas/interact/menus.ts, ui/layout-tabs.ts, ui/menu-spec.ts, ui/icons.ts, main.ts, index.html)

Everything registers from `draw/register.ts`. The engine owns every view, edge class, hatch, dimension link and glyph; the interface reads `/drawviews` (and `?cache=true` for picking), sends `/drawviews` writes or the programmatic `viewdim`, `gdtframe`, `gdtedit`, `datumsym`, `balloon`, `autoballoon`, `bomtable`, `bomupdate`, `centermarks`, `sectionhatch`, `finishmark`, `titleblock` forms, and draws no geometry of its own except tool feedback.

Tools. `ToolHost` catches pointer events on the canvas host in the capture phase while a tool is armed (left button only; move, wheel and middle button still reach the canvas, so panning keeps working) and keeps one window level key listener registered at module load so Escape, Enter and Backspace reach the tool before the canvas controller. A click is a press and release within 5 px; a longer move is a drag, so the detail circle and the break band work both as click, click and as press and drag. The feedback layer is one SVG plus one tag container created at mount; ghost shapes, the selection frame and the five handles are fixed nodes whose attributes are patched, view tags go through `patchList`. Option controls of each tool (section kind and flip, detail scale, break line and gap, dimension kind and direction, finish value) are created once and only hidden or shown, so the tool bar never rebuilds.

Placement. A base view is placed with its centre at the click (the engine centres a view on its `position` because `origin` is the model centre). Projected views are made by dragging from the selected view past its edge: the side is taken from the drop point, mapped to `rel` by the sheet's projection angle (first angle swaps top with bottom and left with right, the same rule as `placement` in the engine) and the engine places the new view in its own arrangement. The move handle sends `position`; the engine applies the alignment constraint of a projected view. Section lines, detail circles, breaks and crop outlines are converted from sheet units to the parent's local millimetres with the one linear map `local = (paper - position) * unit_mm / scale` the DR1 record states; edge picks for auxiliary views and dimensions use the cached curves and DR2's edge ids (`p<pid>` or `<class>.<index>`).

Out of date. A view with `state.status` stale shows an amber badge on its tag and an update button on its list row; error views show a red badge with the engine message. `auto` views rebuild in the engine and only their geometry changes.

Annotation. Editors are Dialogs built once on first use (the glyph list is fetched once, options built once). The frame editor shows a plain text preview of the compartments, never a symbol, and the wording is "geometric tolerance frame"; nothing claims a standard. The annotation settings and document properties dialogs are thin forms over the DR2 routes. Weld symbols are not offered (engine gap).

Shared edits: `ui/layout-tabs.ts` context menu gained two rows (Add Base View, Update Drawing Views) and waits for the layout switch before running the command; the canvas idle menu takes entries from `canvas/interact/menu-extra.ts` (one Drawing submenu while in a layout); the Drawing menu in `ui/menu-spec.ts` is rebuilt from `dw-*` commands.

## Gumball, surface analysis, mesh menu, assemblies, v0.8.0 (u8/*, styles/u8.css, view3d/viewport.ts, view3d/body-view.ts, ui/menu-spec.ts, ui/file-dialogs.ts, ui/icons.ts, main.ts)

All of it registers from `u8/register.ts`; the interface computes nothing and renders engine results.

Gumball. `u8/gumball.ts` is a ViewLayer drawn from `GET /gumball` (origin, axes, alignment). Capture-phase pointer handlers on `vp.host` pre-empt the orbit rig only when a handle is hit. A drag sends the engine preview matrix and the result is applied as a group pose on the selected BodyViews, then cleared after `view3d().refresh()`; a click without movement opens the typed value box. Ctrl-drag relocates, alignment is world, construction plane or object, all engine side.

Analysis colours. A per-body paint material replaces the shared per-colour material inside `BodyView.apply`, so painting never touches shared materials. Values come from the engine binary arrays (`application/vnd.formcad.analysis`); the ramp is a DataTexture and stripes sample by band index so zebra stays crisp. NaN becomes a sentinel and draws the engine undefined colour. Curvature combs and naked edges are engine polylines drawn on the overlay. Section clipping is not applied to painted bodies.

Assemblies. `u8/asm.ts` holds the tree, status, explode list and component world matrices, refreshed by a debounced poll on doc events. Pose previews (mate drive, component drag, explode) are group matrices set through `vp.setPoses` as a delta new * inverse(old world), so nothing is rebuilt while moving. The 409 refusal object `detail` is kept by `u8/net.ts` and rendered by the conflict explainer with one remove button per fix. All lists use `patchList`; rows are built once and patched.

Engine fix made here: `routers/interchange.py` `save_as` routed `.3dm`, `.stl`, `.obj` into the native save and refused them; they now write a copy through `files.write_any` (the document keeps its name and path), matching the file dialog.

Known gaps: engine snap candidates are display only apart from gumball relocate; drag of a fully constrained component returns no poses by design; mate picking has no preview.

## Integration fixes, v0.7.0 (part/register.ts, part/feature-editor.ts, part/api.ts, view3d/mount.ts, view3d/nurbs-ui.ts)

Cold boot 3D entry. Root cause of the intermittent late entry: the controller's idle `create()` could run before the document list arrived, the viewport constructor asked for a grid through `docOrFail`, which threw, and `create` latched `failed = 'No drawing is open'` for the session, so every later `enter` returned at once. The asks now reject (the grid already catches) instead of throwing, `docOrFail` is gone and nothing latches on a missing document. The retry U6 added is removed; auto entry runs from the tree change, from controller creation and once at registration, so it no longer depends on event order. Measured before: 3 failures in 8, 1 in 8, 3 in 8 cold boots; after: 0 in 28.

Bodies without features. A document whose tree has no features asks `GET /bodies` once and enters 3D when any body holds a solid (`summary.solids`); surface-only documents stay in 2D.

Early feature editing. Opening a feature panel calls `View3dController.holdAt(fid)`: the controller fetches `GET /part/scene-at?to=fid` instead of the live scene, the live scene and its delta cache are reset, and the preview asks carry `hold`, so the viewport shows and picks against the body as it stands at that feature, not the final body. Closing the panel releases the hold and reloads. The document rollback is never touched.

Seam badges. The controller compares a cheap signature of the cached bodies (sampled positions per body) before and after each scene load and dispatches `formcad:scene-touched` when it changed; the analysis layer clears its seams on it. A reload with no geometry change, which every selection or command event causes, leaves the badges. The scene `rev` is 0 in the stream, so the signature, not the revision, decides.

The `model-tolerance` 404 seen in the console by U6 came from an engine started before U7 mounted the route (U6's engine log shows the requests and the 404 for a route added later); with the current tree it does not occur (28 cold boots, no response of 400 or more).

## Part feature tree, feature panels, configurations, materials and mass, v0.7.0 (part/*, view3d/refgeo.ts, view3d/viewport.ts, view3d/mount.ts, ui/dock.ts, ui/dom.ts, ui/menu-spec.ts, ui/icons.ts, styles/part.css)

Everything part-related lives in `part/` and registers itself from `part/register.ts` (dock panels `features`, `configurations`, `refgeo`, the `pt-*` commands, the Part menu, a 3D toolbar and three dialogs). The interface renders engine state only: the tree, the type schemas, the hole table, reference frames, configs, materials and mass numbers all come from the routes; nothing is computed here. The feature panel is one overlay inside the 3D host with a form per type cached after its first build, so reopening a type is a visibility flip. A panel is schema driven: each parameter slot becomes a field, each reference slot a `RefSlotView` with chips and a pick toggle. While a pick toggle is on, `Viewport3D.onPick` receives the selection instead of the viewport selection store.

Live preview is `POST /part/preview` (engine side, see the engine log). The scene it returns goes into a separate group through `setPreview`, so the real bodies are untouched and a preview, a refusal or a cancel never changes what the tree shows. OK awaits one last preview, commits, reloads the scene, then clears the preview, so there is no frame without a body. An empty or refused preview blocks OK (`lastBad`) so an error feature cannot be created by accident.

Hole sizes: the engine table is shown as is. Each row carries its status in the select label and a note under it; the notice text is shown above the fields. No value is presented as a standard. Empty clearance, counterbore, countersink and tap rows stay empty and the user types numbers.

The rollback bar is a zero height node with an absolutely drawn line, so moving it never shifts a row (measured layout shift 0 under 4x CPU and 1.6 Mbit/s). It is one cached node, placed alone by `paint`: when the engine moves the bar, only that node moves instead of every row being reinserted. Drag listeners sit on `window` because the bar node moves in the DOM during a drag and loses pointer capture. Reorder is offered only where `canmove` says yes; the verdict is cached per drag and a refusal shows the engine message.

Shared edits: `ui/dock.ts` `place` now picks the smallest greater `order` instead of the first in insertion order (panels registered late landed at the bottom). `ui/dom.ts` `patchList` now runs `update` right after `create`, so a created row is filled by the same code that patches it; existing callers only had their update run twice on first paint.

Sketch entry: a face pick or a plane from the chooser creates the sketch in the engine, the 2D canvas opens on `sketch:<Name>` and a banner offers Finish Sketch, which exits, rebuilds and returns to 3D. Known limits: edits to an early feature pick against the final body, so the engine may refuse refs from later features; a document with bodies but no features does not enter 3D by itself.

## Curves and surfaces interface, turn 7 (view3d/layer.ts, curve-layer.ts, analysis-layer.ts, nurbs-api.ts, nurbs-ui.ts, diag-store.ts, ui/panels/bool-diag-panel.ts, model-tol-rows.ts)

The viewport takes extra layers through `ViewLayer` (`addLayer`, `project`, `rayAt`, `fitLayers`, optional `bounds`); nothing else in the viewport knows about curves. Curves are not in the binary scene, so `CurveLayer` reads `GET /curves` and draws them in the 3D view; control and edit point markers are painted on the 2D overlay and hit-tested with the same projection, so no point sprites exist in the scene. Grip ids come from the engine grips route (`c<i>`, `e<i>`), 3D positions from the curves route (the grips route is XY only). Drags are caught on the host in the capture phase, before the rig, only when a marker is under the pointer; a control point drag previews locally with a de Boor evaluation (non-periodic curves), an edit point drag moves the marker, and release sends one `/grip` stretch (one undo step) and patches the line from a refetch. The drag plane is horizontal through the grip when the view is not near edge-on, else camera facing; the engine keeps z.

Reports reach the interface through `GET /surface-last` (the runner memory the surface commands already fill, plus a sequence number added to `keep_report` and `do_naked`) because a typed or menu run returns no result record. The interface listens to `formcad:command-state` and `formcad:cmdline-applied`, reads the report when the sequence moved and the command output names it, and never replays a report on reload. Seam state is three-way: green when gap, angle and curvature are inside the document tolerances, amber when only curvature is outside, red otherwise. Booleans open the diagnostics panel only when they fail or when the run was a check; a passing BOOLOP stays quiet. Report coordinates are millimetres and are divided by the drawing scale before drawing. Model tolerance rows sit in Document Info and call MODELTOL.

The layout tab list and the viewport scale popover now patch their buttons in place (`patchList`, bold weight toggled only when it changes) instead of replacing the children on each opening. ## Constraints, parameters and automation (canvas/cmarks.ts, canvas/interact/constraint-layer.ts, io/api-param.ts, io/api-auto.ts, ui/param/*, ui/auto/*, styles/u5.css) · _v0.6.0

Constraint glyphs and dimension labels are not prims in the GPU buffer: the engine sends one `cbar` prim per sketch item and the store keeps it in `bars`, so a display delta patches marks in place and the 2D overlay repaints them with greedy overlap avoidance (cached by key, 600 marks at most). Status colours live in `build.ts emit`: an engine `rgb` overrides the colour with flag 0, and a fully defined item with no `rgb` uses ink. Hover draws the related objects in the accent colour; right click on a mark opens its menu, double click on a dimension label opens an inline expression editor. A refusal (409 or `result.refused`) opens the Conflict Explainer, de-duplicated by doc, rev and explanation. Parameters Manager is a non-modal Dialog so the drawing stays live, refreshed on the doc event (120 ms debounce); errors stay inline in the Value cell and a message line. The status chip and the automation pill sit before `.cv-st-hint` at fixed width with `visibility: hidden` when idle, so nothing shifts. Typed commands only reach an interceptor when the engine knows the name, so LISP Console and Macro Recorder open from the Tools menu. `app.ts` is the composition root: `mountShell()` builds the shell template once and returns every host element; `onShellMounted` and `onCapabilities` let sections register without editing `startApp`. `shell-part1.ts` registers the title bar, menus, tabs, Home and status bar; `shell-part2.ts` registers Preferences, the palette, the command line and the dock; each is one import in `main.ts`. `onCapabilities` registers at module load so the status bar never shows "Engine offline" before the first answer.

Menu items that are engine commands run `POST /api/docs/{id}/command` and show the engine's answer; nothing in the menus is a dead item. Drafting toggles in the status bar read and write system variables (AUTOSNAP bits 8 and 16 for polar and tracking, OSMODE bit 16384 for running snaps) and follow `sysvar` events; engine variables are the source of truth for drafting options, so the preference store keeps only interface settings. Edit shortcuts are left to a focused text field. The command palette key reads `Shift+Mod+P` because `comboOf` orders modifiers Alt, Shift, Mod.

The dev server injects the token meta by reading the engine's token file and stamps the header on proxied requests; the built interface gets the meta from the engine. Font preloads point at the dev paths and fall back to the CSS imports in the build.

Removed from the formvis carry-over: user skins, favourite themes, the dock-boot script and the remembered-values history; they belong to the image editor.
